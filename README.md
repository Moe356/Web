# نظام إدارة محطة عبد المحسن الكاظمي
## قسم المجاري – بلدية الكاظمية المقدسة – أمانة بغداد

منصة تشغيلية متكاملة لإدارة محطة عبد المحسن الكاظمي لرفع ومعالجة مياه الصرف الصحي وشبكات المجاري التابعة لبلدية الكاظمية، مصممة بالكامل باللغة العربية مع دعم تخطيط RTL والتبديل إلى الإنجليزية.

---

### الوحدات والصفحات المنجزة (Modules):

1. **تسجيل الدخول وصلاحيات الأدوار (Authentication & RBAC):**
   - 8 أدوار وظيفية معتمدة:
     - مدير النظام العام (Super Administrator)
     - مدير المحطة (Station Manager)
     - مشرف الوجبة / الشفت (Shift Supervisor)
     - مأمور التوزيع والعمليات (Operations Dispatcher)
     - مهندس / فني صيانة (Engineer / Technician)
     - سائق / عامل ميداني (Driver / Field Worker)
     - مسؤول الموارد البشرية (HR Officer)
     - مدقق ومراقب مالي وإداري (Read-only Auditor)
   - محاكاة صلاحيات على مستوى الواجهة لأغراض العرض فقط؛ لا تمثل مصادقة أو تفويضاً آمناً على الخادم.
   - وضع العرض التجريبي (Demo Mode) بمحددات واضحة وبيانات واقعية وإمكانية استعادة البيانات بضغطة زر.

2. **لوحة القيادة والمؤشرات (Dashboard):**
   - مؤشرات مشتقة من سجلات العرض التجريبية لأوامر العمل النشطة والطارئة.
   - حالة جاهزية أسطول الآليات (شاحنات سحب، صاروخيات، حفارات).
   - عرض قيم تدفق وعمق تجريبية؛ لا يوجد اتصال فعلي بحساسات المحطة ضمن المشروع الحالي.
   - مخطط بياني لتوزيع إنجاز البلاغات الأسبوعي.
   - عرض محلي لسجل نشاط تجريبي قابل للتغيير وليس سجلاً رقابياً رسمياً.

3. **أوامر العمل والشكاوى الميدانية (Operations & Work Orders):**
   - تسجيل البلاغات مع تحديد القاطع (الكاظمية القديمة، العطيفية، النواب، الجوادين، براثا، المحيط، محلة 421، محلة 425).
   - مسار مراحل العمل (Workflow): جديد -> قيد المراجعة -> تم التكليف -> في الطريق -> في الموقع -> قيد التنفيذ -> بانتظار مواد -> مكتمل -> معتمد ومغلق.
   - اشتراط تسجيل سبب رسمي ومبرر واضح عند إلغاء أي بلاغ.
   - اشتراط تسجيل تقرير الإنجاز الفني قبل إغلاق أي بلاغ.
   - قسيمة عمل ميدانية قابلة للطباعة الرسمية.

4. **مركز التوزيع والتحكم الميداني (Live Dispatch Center):**
   - لوحة عمليات تفاعلية تعتمد على بيانات العرض المحلية.
   - مؤشرات الأولوية القصوى وحالات الطوارئ.
   - جدول إحداثيات المواقع الميدانية في قاطع الكاظمية.

5. **أسطول الآليات والمعدات (Fleet & Machinery):**
   - متابعة صهاريج السحب (12 و 14 م³)، الشاحنات الصاروخية ذات الضغط العالي (250 بار)، وتناكر المياه والحفارات.
   - حظر تكليف الآليات المسجلة (خارج الخدمة / معطلة) في أي أمر عمل لحماية سلامة التشغيل.
   - متابعة عدادات الكيلومتر وساعات التشغيل ومستويات الوقود ومواعيد الفحص الدوري.

6. **إدارة الصيانة والأعطال (Maintenance Management):**
   - أوامر الصيانة الوقائية والعلاجية للآليات ومضخات المحطة.
   - احتساب تكاليف المواد والأجور بالدينار العراقي وساعات التوقف (Downtime).
   - تنبيهات جاهزية الآليات الحرجة.

7. **تشغيل محطة الرفع والأحواض (Station Operations):**
   - لوحة تحكم الوحدات الخمس الرئيسية (P-01 إلى P-05).
   - مؤشرات التدفق، حرارة المحركات، والاهتزاز.
   - حالة التغذية الكهربائية (الشبكة الوطنية 395V vs مولدة Perkins 1250 KVA).
   - المصافي الميكانيكية لحجز الشوائب ووحدة المعالجة الحيوية لتقليل الروائح (Biofilter).
   - محضر تسليم الشفت اليومي المعتمد من مهندس التشغيل المناوب.

8. **الوقود ومخزن قطع الغيار (Fuel & Inventory):**
   - وصولات صرف الديزل مع قراءات العدادات والتكلفة الرسمية.
   - سجل قطع الغيار مع حدود الطلب الحرج (مثل موانع التسرب Mechanical Seals والصمامات).
   - حركة الإدخال والصرف المخزني مع تدقيق الأرصدة ومنع الرصيد السالب.

9. **إدارة الكادر الوظيفي وشؤون الموظفين (Staff Directory):**
   - دليل الكوادر، الأرقام الوظيفية، والشهادات والخبرات.
   - حجب الملاحظات السرية والعقوبات الانضباطية وحصرها بمسؤول الموارد البشرية والمدير العام.

10. **الحضور وجداول الوجبات (Attendance & Shifts):**
    - الشفتات الثلاثة (صباحي، مسائي، ليلي/طوارئ).
    - تسجيل الحضور والانصراف الميداني.
    - طلبات تبرير وتصحيح الدوام مع مسار مصادقة المشرف المباشر.

11. **الكتب والقرارات والأوامر الإدارية (Administrative Correspondence):**
    - أوامر إدارية ملزمة، تعاميم سلامة، وطلبات إجازة.
    - توليد أرقام إشارية رسمية متسلسلة وتاريخ الإصدار.
    - ترويسة بلدية رسمية قابلة للطباعة المباشرة مع مسار توقيع العلم والاستلام.

12. **مؤشرات الأداء والسجلات (Performance Appraisals):**
    - مؤشرات واقعية مستندة إلى سجلات أوامر العمل وساعات الحضور.
    - سجل العقوبات والتنبيهات الإدارية المحمي رقابياً وقانونياً.

13. **التقارير والمؤشرات والإحصائيات (Reports & Analytics):**
    - شفافية تامة في معادلات احتساب المؤشرات (نسبة الحل، جاهزية الأسطول، التوقف).
    - تصدير فوري لبيانات البلاغات بملف CSV.
    - طباعة تقارير الأداء الرسمية.

14. **سجل النشاط التجريبي (Demo Activity Log):**
    - سجل نشاط تجريبي محفوظ محلياً ويمكن تغييره أو مسحه.
    - يسجل اسم الدور والوقت والتفاصيل محلياً؛ عنوان IP الحقيقي غير متاح من تطبيق المتصفح هذا.
    - تصدير سجل النشاط التجريبي بصيغة JSON.

15. **الإعدادات والتكوين (Settings):**
    - بيانات المحطة والبلدية وأرقام الخط الساخن.
    - مصفوفة الصلاحيات (RBAC).
    - تنزيل نسخة احتياطية لكامل بيانات النظام واستعادة البيانات الافتراضية.

### تعليمات التشغيل والتثبيت (Setup Instructions):

1. **المتطلبات الأساسية:**
   - Node.js إصدار 22.12 أو أحدث (أو 20.19 فأحدث، بما يتوافق مع إصدار Vite المستخدم).
   - npm أو pnpm.

2. **التشغيل محلياً:**
   ```bash
   npm install
   npm run dev
   ```
   يتم تشغيل المنظومة على المنفذ `http://localhost:3000`.

3. **بناء النسخة الإنتاجية (Production Build):**
   ```bash
   npm run build
   ```

### ملاحظة مهمة حول الجاهزية (Demo Readiness Notice)

- **الحالة الحالية:** هذا مشروع عرض تجريبي يعمل في المتصفح ويستخدم `localStorage` وبيانات افتراضية. قد تبقى التغييرات محفوظة في المتصفح نفسه، لكنها لا تتزامن تلقائياً بين الموظفين أو الأجهزة.
- **تسجيل الدخول والأدوار:** حسابات العرض وتبديل الأدوار مخصصة لتجربة الواجهة فقط. لا توجد مصادقة حقيقية أو صلاحيات مفروضة على خادم في النسخة الحالية؛ لا تستخدم بيانات حقيقية أو سرية.
- **سجل النشاط:** السجل محلي وقابل للتعديل أو الحذف، ولا يوفر سجلاً رقابياً غير قابل للعبث أو تحققاً تشفيرياً.
- **أجهزة المحطة:** لا يوجد تكامل مثبت في هذا المشروع مع SCADA أو PLC أو حساسات أو مضخات حقيقية. أي قيم تشغيلية ظاهرة هي بيانات عرض ما لم يثبت خلاف ذلك عبر تكامل فعلي.
- **الخدمات الخارجية:** لا يحتوي المشروع الحالي على تكامل Firebase مثبت. يتطلب تشغيل متعدد المستخدمين إعداد backend آمن، ومصادقة فعلية، وقواعد تفويض على الخادم، وقاعدة بيانات، ونسخاً احتياطية، واختبارات أمنية. يتطلب أي ربط بالأجهزة أو الخرائط أو الرسائل إعداداً وتطويراً واختبارات منفصلة.
- **التحقق:** يجب تنفيذ `npm install` ثم `npm run lint` و`npm run build` في بيئة تسمح بتنزيل الحزم قبل اعتبار المشروع قابلاً للبناء. لم يتم تأكيد نجاح هذه الاختبارات في بيئة التحرير هذه.


## Performance metrics and technical supervisor evaluation

- The Performance page now calculates each employee's completed work-order count from linked work orders whose status is `completed` or `verified`.
- Select the count in the employee row to inspect the linked work orders, status, completion notes, and recorded duration.
- Users with the existing employee-edit permission can enter a 1–5 technical supervisor rating and notes. The rating records who entered it and when.
- Work orders can be linked to an employee from the employee's work-order details dialog, provided the current role has permission to edit work orders.
- Attendance compliance is calculated from attendance records for that employee. If there are no attendance records, the page displays that no records are available rather than showing a fabricated percentage.
- This is still a browser-local demonstration. Ratings and assignments are persisted in localStorage and are not shared between different computers.
